# Open-weight "builder" LLM candidates for one RTX 5090 (32 GB) + 64 GB RAM — research notes

Date of research: 2026-11-04. Target workload: strong reasoning + agentic Python coding (numerical code in a sandbox, long multi-turn tool loops, 32k–128k context).

## 0. How to read this file (verification legend)

Network in the research sandbox allowed WebFetch **only for github.com**; everything else came from WebSearch snippets. Every row/number is labelled:

- **primary (github.com)** — read directly from a GitHub README / source file / discussion of the model org, llama.cpp, vLLM, etc.
- **secondary coverage** — a search snippet from a non-GitHub secondary source (vendor blog as quoted by third parties, Unsloth docs, Artificial Analysis, press), or a third-party GitHub README that is not the vendor's.
- **search snippet only** — a single snippet, not cross-checked.
- **unverified** — from prior knowledge or inference; not confirmed in this run.
- "unknown" means it was not located in this run; nothing was invented.

Benchmarks are vendor-reported unless marked "independent". SWE-bench Verified numbers from Qwen use Qwen's internal scaffold (bash + file-edit tools) and are not comparable across labs (secondary coverage).

Units: GB = decimal (file listings), GiB = binary (llama.cpp reports). KV-cache arithmetic in §1c uses GiB.

### 1c. KV-cache arithmetic used above

Formula (f16 cache): **bytes/token = L_kv × 2 (K and V) × n_kv_heads × head_dim × 2 bytes**, where L_kv counts only layers that keep a growing KV cache (full-attention layers; sliding-window layers hold ≤ window tokens; Gated-DeltaNet/Mamba layers hold a fixed recurrent state). q8_0 KV ≈ 1.0625 bytes/element (×0.53 vs f16); llama.cpp defaults compile FlashAttention kernels for q4_0, q8_0, f16, bf16 KV (`GGML_CUDA_FA_QUANTS`, primary docs/build.md).

## 3. Fine-tuning feasibility on 32 GB

Rules of thumb (Unsloth "Requirements" page, stated as **absolute minimums**; secondary coverage):

| Base size | QLoRA (4-bit base + LoRA) | LoRA (16-bit base) |
|---|---|---|
| 3B | 3.5 GB | 8 GB |
| 7B | 5 GB | 19 GB |
| 14B | 8.5 GB | 33 GB |
| 32B | 26 GB | 76 GB |
| 70B | 41 GB | 164 GB |

- Measured peak reserved VRAM at 2,048-token sequences (third-party, secondary): 7–8B 7–12 GB; 13–14B 14–18 GB; 32–34B 22–26 GB; 70B 42–48 GB. A 2026 planning guide estimates QLoRA 14B ≈ 14 GB, 32B ≈ 28 GB.
- **30B-A3B MoE**: Unsloth's Qwen3 guide: Qwen3-30B-A3B QLoRA "works on just 17.5GB VRAM" (full 16-bit weights converted to 4-bit on the fly); 16-bit LoRA on the same model uses 63 GB (secondary). gpt-oss-20b: "20B works on a 14GB GPU and 120B on 65GB VRAM" (Unsloth README, primary); 2026 MoE post says 12.8 GB (secondary).
- **Caveat for Qwen3.5**: Unsloth's Qwen3.5 fine-tune guide says QLoRA (4-bit) "is not recommended … no matter MoE or dense" (secondary) — plan on 16-bit LoRA, which for 27B/35B needs ≈ 60–76 GB and does not fit a 5090. A GitHub discussion also notes bnb-4bit QLoRA on recent MoE models was "still a WIP" (secondary).
- **QLoRA paper repo** (primary): "finetune a 65B parameter model on a single 48GB GPU"; NF4 + double quantization + paged optimizers.
- **Full fine-tuning**: ≈ 16 bytes/param with mixed-precision AdamW (2 weights + 2 grads + 8 Adam states + 4 FP32 master) → 7B ≈ 112 GB, 27–32B ≈ 430–510 GB, before activations (secondary, multiple). 8-bit Adam brings an 8B model to ≈ 48 GB static; FlashOptim-style tricks reach 5–7 bytes/param (secondary) — still > 32 GB for anything ≥ 7B. **Full FT of any builder candidate is infeasible on a 5090.**
- Practical read for a 32 GB card: QLoRA is comfortable for ≤ 14B dense and 30B-A3B-class MoE (Qwen3, gpt-oss-20b); 27–32B dense QLoRA is at the limit (26–28 GB minimum, short sequences, batch 1); Qwen3.5/3.6/3.8 should be LoRA'd in 16-bit (does not fit) or QLoRA'd against Unsloth's advice.

## 6. Reality check: evidence of long agentic numerical / ML-engineering loops

Benchmarks that actually resemble the target task (sandboxed ML engineering):

- **MLE-bench** (75 Kaggle competitions; 24 h, 36 vCPU, 440 GB RAM, one 24 GB A10 per run; primary README, leaderboard paused 2026-04-24). Open-weight entries: DeepSeek-V3.2-Speciale (ML-Master 2.0) **56.44 %** any-medal; DeepSeek-R1 36.44 % (InternAgent) / 29.33 % (ML-Master); Llama-3.1-405B 3.33 % (AIDE). **No model that fits a 5090 appears on the MLE-bench leaderboard.**
- **RE-Bench** (METR): no open-weight model results were located in this run (unknown).
- **Terminal-Bench 2.0/2.1**: the open-weight top entries are DeepSeek V4 Pro 0813 67.9 % and Kimi K2.6 66.7 % (aggregator mirror, 2026-10-29), GLM-5.1 69.0 % (secondary) — all far too large for a 5090.
