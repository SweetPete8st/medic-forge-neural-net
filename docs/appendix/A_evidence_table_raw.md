## Section B — Per-source notes with quotes

### B1. MIT CSAIL "Sparks of Weight-Space Programming" — logs repo `RikiyaT/lm_understand-logs` (primary)

**Repo-level facts (README).** Holds "complete logs" for the blog: prompts, replies and reasoning summaries, code run with output, evaluations, and the networks read/written. Builder: OpenAI `gpt-6-astra` ("Astra") via the Codex CLI. All built-in Codex tools disabled (shell, file editing, web search, image viewing, sub-agents, plugins). Where code was allowed (exps 3, 6, 7, 8) a bubblewrap sandbox ran one Python block per turn (no network, persistent `/work`, time limit). "All 1,125 turns are audited as tool-free." Not included: Gemma fine-tunes (~17 GB), intermediate activations/draft networks, exp 3 Python corpus text (manifest + rebuild script instead), GPQA question texts. Repo had 894 stars / 114 forks, 1 commit on main, at fetch time. Licenses: logs/data/networks CC BY 4.0; scripts MIT; MinAtar source in exp5 prompts GPL-3.0; third-party benchmarks keep their own licenses.

**Harness (primary).** `harness/instructions.md` is the single line **"Answer the user's request."** [primary quote]. `harness/codex_config.toml`: approval never, sandbox read-only, web search off, agents off, 26 feature flags off; header comment says the default is "no tools" and experiments needing tools add their own MCP server explicitly. **Note: the committed config names model `gpt-6-luna` at reasoning effort `medium`,** while every experiment README/run record says `gpt-6-astra` at high/xhigh/max; I could not see where the per-run override happens (presumably CLI flags). `harness/sandbox.py`: `bwrap --unshare-all --die-with-parent --new-session --clearenv`, `/usr` read-only, python `-I`, `TIMEOUT = 900`, `MEM = 96 << 30` via RLIMIT_AS, `MAX_OUT = 20_000` chars, stderr last 6,000 chars, `CUDA_VISIBLE_DEVICES=""`, `OMP_NUM_THREADS=8`; prelude defines `load/save/saved/inp/mv`, `PASS = 81` — i.e., the committed sandbox.py is the exp6 (Go) variant; exp3's README states a 600 s limit, so limits differed per experiment.

**Exp 1 (primary).** Four PPO actors (best of 3 seeds each; 999,997,440 training steps). Given: release description, open question with no candidate list, all 17,253 actor weights as text (3 dp). No tools. One reply per run. 4/4 correct; Freeway answered as "Frogger", mapped by keyword scorer. Usage: ~73.7K input tokens; 1,679–1,838 output tokens (833–1,034 reasoning); 71–107 s wall per run.

**Exp 2 (primary).** Three DDPM MLPs (23,824 weights). Prompt includes **"Do not do any forward-pass calculation"** [primary quote]. 3/3 correct, confidence 84/77/88%. Astra drew every shape as a hollow outline; models generate filled shapes. Sample-quality check: 1,000 samples per model classified 99.4/98.4/100% as intended shape.

**Exp 3 (primary).** Weights of the four blocks were *not* in the message; Astra read them in the sandbox. Forbidden: any forward pass, search. Allowed: linear algebra on weight matrices. Authors "reviewed all code runs and state none ran the network or a layer on an input." Six conversations, 6–11 code runs each; all six correct top answer, copying heads matched ground truth (induction score > 0.2; `scores.json` uses a stricter 0.3 cutoff that differs from the post). The Python corpus is 324,932,625 chars, 81.5% exactly identified, text not released.

**Exp 4 (primary).** Environment is Kinetix `l/h2_car_ramp` (not MountainCar). Model output 51 edit statements in a small edit language (e.g., `actor0.W[6, 122] = 80`), applied in order to the rounded network; 6,073 / 171,664 weights changed (3.54%); result 256/256 and 1,024/1,024 vs 0/256 before. Diagnosis: velocity-sensitive throttle/coast controller losing momentum on the ramp; fix adds a side path that backs up then drives left, handing off to the trained net. One trial, no feedback, no retry.

**Exp 5 (primary).** Model received task + scoring rules, game rules and exact MinAtar source file, I/O format, architecture, "edits" language; **no training data, loss, gradients or feedback**; one reply per game. Parsing note: first reader rejected some list formatting (116/122 and 51/55 statements read); reader fixed and same replies re-read without a new query.

**Exp 6 (primary).** 1,480,274-weight Go net; "passes" = games pass (≤128 games vs practice opponents) or positions pass (≤256 positions with logits/activations). Forbidden: training/fitting, search, running the net outside passes. Hidden scoring: 2,000 games vs each of two small PPO nets. Budget 50: 84.0% / 80.8%; vs same-size PPO 74.2/70.0/78.5%. Budget-50 run: 90 turns, 39 Python runs, 3 h 52 min including ~2 h 15 min disk-quota pause. A v2-prompt run and a 1-pass run exist but are excluded from the post.

**Exp 7 (primary).** Weights-only attempts 1–3 all "unable to tell" (1/3 = chance via forced tie-break; runs per pair up to 17/20/22); attempt 4 stopped early, no score.json. Prompt changes between attempts: attempt 2 added "a thorough investigation usually uses most runs", attempt 3 added "Do not give up." Attention-tool round 3/3 correct. Harness crash for first 40 min of attention round, retried transparently; folders r1–r4 missing.

**Exp 8 (primary).** Prompt (`runs/p50c/message.txt`) explicitly names the loop failure as in scope: **"if the model often fails because it repeats itself and never finishes, finding and fixing what drives that repetition counts."** [primary quote]; failures include **"being cut off at the token limit (often while repeating itself in its thinking)"** [primary quote]; **"repairing a specific failure inside the thinking (such as repetition) is in scope"** [primary quote]; out of scope: "making the model skip its thinking or close it early regardless of the problem." Protected tensors: final norm, embed_tokens/lm_head, whole-tensor constant multiplications; "global output-sharpening or flattening knobs" not wanted. Agent must "EXPLAIN EVERY STEP" (added at turn 52/16/29 in p10c/p25c/p50c), keep `/work/notes.md`, and submit `/work/edited` when all passes are used. Notices: `003_submit_best.txt` changed the rule to submit "the best edit you found, the candidate with the best measured paired gain" even if not statistically significant, and not to restore original weights; `004_failure_counts.txt` corrects an over-count of the "no_answer_finished" category in earlier pass summaries. Interim GPQA figure of 24.5 in the benchmark figure was at 149/198 questions; final 22.7.

## Section C — Bearing on a stateful patient simulator

Question: *can an LLM compile an explicit physiological specification into a recurrent/stateful network of 10K–1M weights, and can a 30B-class open-weight model do it locally?*

| Source | Direct evidence or analogy | One-sentence reasoning |
|---|---|---|
| MIT Exp 5 (MinAtar from source code, 20K weights, no tools) | analogy (closest MIT item) | A frontier closed model wrote a working 20K-weight *feedforward* controller one-shot from an explicit game-source spec, which is the right size and the right "spec→weights" direction but stateless and not reproducible by open models at the same level (ATI: Opus 5.5 112 vs 517; DeepSeek-V4-Pro 5.5). |
| MIT Exp 6 (Go, 1.48M weights, Python + passes) | analogy | Shows code-plus-feedback can hand-build a 1.5M-weight feedforward net that beats same-size PPO, but the builder is closed, the net is stateless, and the "passes" feedback loop is essential (54% → 84%). |
| MIT Exp 4 (car repair, 171K weights, in-context) | analogy | One-shot in-context repair of a dynamical-control policy is suggestive for "fix a simulator bug", but it is a single trial that openwsp's Astra re-run failed (0/1,024). |
| MIT Exps 1–3, 7 (reading) | analogy only | Reading what a net does is not writing one; and Exp 7 shows weights-only reading fails on a 270M LM without activation tools. |
| MIT Exp 8 + Gemma follow-up | analogy only | Editing a pretrained LM to remove a loop is a different task from compiling a spec; the Gemma result shows editing could not *add* ability, which argues against expecting "compile new physiology into an existing net" to work by editing. |
| Khaliq re-run; KidIkaros; openwsp calibration | none (confirms the artifact only) | They confirm the released Qwen edit works; they say nothing about spec compilation. |
| Critiques (Honnibal, Goedecke, Nanda, Keruac, HN, Latent Space) | indirect | Their consensus — the real capability is "LLM writes analysis/construction code" rather than "LLM emits numbers" — points the simulator project toward the code-construction route (csinva, ctrimm) and away from in-context numeric weight emission. |
| csinva toy tasks (Claude writes closed-form transformer weights via code) | **direct for the compile-by-code route**, feedforward only | An off-the-shelf Claude agent, with an accuracy feedback loop, compiled explicit algorithms (adders, sorters, parity, bit conversion) into exact weights of 174–22M params within ≤3 attempts; but targets are autoregressive transformers, not recurrent ODE-like state, and the three real-data tasks failed/were invalid. |
| csinva systematic tests (Opus 5.5 predicting edit effects) | direct negative for in-context reading of a 0.8B net | Reading raw weights barely helps predict edit effects (+0.06 correlation), so planning edits to a large stateful net purely from weights is unsupported. |
| ctrimm benefits-formula nets | **direct for "explicit spec → exact small net"**, stateless | Three different LLMs (incl. open-API GPT-5.6 Sol, Gemini 3.1 Pro) compiled statutory piecewise-linear formulas into ~1.3K-param nets exact to 1e-12, and a 2-parameter surgical update worked — the strongest existing evidence that explicit rule specs compile reliably, though with no recurrence/state. |
| Alan Turing Institute cross-model table | direct on the "which model can do it" axis | Only the Sep-2026 frontier generation writes strong nets; DeepSeek-V4-Pro (the only open-weight model tested) scored near zero on writing and at chance on reading, and no ~30B open model was tested. |
| Willison (Qwen 3.8 27B local, reading) | direct for the "30B-class local" axis, reading only | A 27B open model can *read* 17K-weight nets in context (3/4) but needs 45–60+ minutes per answer and nothing shows it can write. |
| HarleyCoops (qwen3.6-35b-a3b editor) | weak direct for "open ~35B editor" | An open 35B-A3B model can propose accepted scalar edits on a 17K net under a verifier, but only trivial ones (2 sign flips) and later versions failed to submit edits at all. |
| Krentsel; nihilistau; tdotlab; HarleyCoops Angel | analogy / weak direct | Reinforce that writing ability is frontier-generation-gated and that non-frontier edits can backfire (tdotlab P64 → "Wait, wait, wait"). |
| RASP / Tracr | **direct for deterministic compilation**, wrong target class | Proves explicit algorithms can be compiled into exact transformer weights by a compiler, suggesting an "LLM writes RASP/program, compiler emits weights" pipeline; but Tracr targets sequence-processing transformers, not continuous-state recurrent dynamics, and is archived. |
| Arditi (rank-one refusal edit) | analogy | Demonstrates that single-direction weight edits on 1.8–72B LMs are cheap and reliable, the mechanism the Qwen edit reuses, but it is behaviour removal, not spec compilation. |
| HyperNetworks | analogy | Generated *recurrent* (LSTM) weights exist, but only via gradient-trained generators, not from a spec. |
| Text2Weight / NeuroGen | analogy | Text-conditioned weight generation requires a training set of checkpoints for the target family; no such set exists for custom physiological simulators. |
| Survey 2603.10090 | context | Maps the field; confirms no established "spec → stateful net via LLM" line of work. |

**Net reading for the simulator question:** direct evidence exists only for (a) compiling explicit *stateless* algorithms/formulas into small nets via LLM-written code (csinva, ctrimm, Tracr), and (b) a 27B local model being able to read, slowly, a 17K-weight net. There is no evidence anywhere in this set that any model has compiled a spec into a *recurrent/stateful* network, and the only open-weight writers tested (DeepSeek-V4-Pro; qwen3.6-35b-a3b) performed near zero or trivially.

## Section D — Contradictions with the brief, and what could not be verified

**Claims in the brief that the sources contradict or qualify**

1. **"Built-in tools disabled"** is confirmed, but note the committed `harness/codex_config.toml` names model `gpt-6-luna` at effort `medium`, not `gpt-6-astra`; the experiment READMEs and run records say `gpt-6-astra` at high/xhigh/max. I could not locate the per-run override. Also, secondary coverage sometimes says "all 1,125 turns were tool-free" as if no code ran; the audit covers Codex built-in tools only — Python ran via the harness's own fenced-code sandbox in exps 3, 6, 7, 8.
2. **"131,072 = 0.016% of Qwen3.5-0.8B."** 131,072 (2×64×1,024) is primary; "0.016%" is the blog's figure and is not stated in the exp8 README; it is consistent with a 0.8B denominator (my arithmetic 0.0164%). 130,188 of the 131,072 actually differ after bf16 rounding.
3. **"The other six completed runs gained at most 6.2 points."** Consistent with RESULTS_excerpt: the six non-p50c Qwen rows (0-pass v2, 5-pass v3, 10 v3, 25 v3, 10 v4, 25 v4) top out at 14.1 (my arithmetic: +6.2). Qualifications: three of those six submitted no edit at all (score = baseline); two unsubmitted candidates (p05c 8.6, p10d 10.1) and a prompt-v5 series with no values also exist, so "six completed" depends on how one counts; the v3 and v4 25-pass rows have identical scores (14.1 / 25.1), which I could not explain (same run relabelled, or coincidence).
4. **"~20 hours and 80 Python runs with a prompt that pointed at the loops."** Confirmed: p50c 20.3 h (of which 4.7 h was an outage wait, so ~15.6 h active), 80 Python runs, 158 turns, 4 handoff conversations; the prompt explicitly lists repetition/token-limit cut-off as an in-scope failure (quotes in B1).
